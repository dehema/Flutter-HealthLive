# HealthLive 前端开发指南

> 本文档面向 **Flutter 客户端** 开发人员。后端由 **Go** 实现，数据存储使用 **PostgreSQL**。前端仅负责 UI 展示、用户交互与 API 调用，不直接访问数据库。

---

## 1. 项目定位与职责边界

| 层级 | 技术 | 职责 |
|------|------|------|
| 客户端 | Flutter (Dart) | 页面渲染、路由、状态管理、本地缓存、调用 REST API |
| 服务端 | Go | 业务逻辑、鉴权、数据校验、聚合查询 |
| 数据库 | PostgreSQL | 持久化存储（内容由后端管理，前端不可见） |

**前端不负责：**

- 数据库连接与 SQL
- 内容入库、审核、发布流程
- 服务端业务规则（如权限判定、数据统计）

**前端负责：**

- 将后端返回的 JSON 映射为 UI 模型并展示
- 处理加载中 / 空数据 / 错误 / 重试等交互状态
- 可选的本地缓存（收藏、最近浏览、离线阅读）
- Token 存储与请求头注入（若后端启用鉴权）

## 2. 业务模块说明

应用为生活向健康科普客户端，围绕 **作息、运动、饮食** 三类内容，向用户展示相关益处与建议。各模块与后端 API 一一对应，便于前后端并行开发。

### 2.1 模块总览

```
┌──────────────────────────────────────────────────────────────┐
│                        App Shell                             │
│  主题 · 路由 · 全局错误处理 · 网络客户端 · 环境配置              │
└──────────────────────────────────────────────────────────────┘
         │              │              │              │
    ┌────┴────┐   ┌─────┴─────┐  ┌─────┴─────┐  ┌─────┴─────┐
    │  Home   │   │ Category  │  │ Content   │  │  User     │
    │  首页   │   │ 分类浏览   │  │ 内容消费   │  │ 用户中心   │
    └─────────┘   └───────────┘  └───────────┘  └───────────┘
```

### 2.2 模块详细说明

#### App Shell（应用壳）

| 项 | 说明 |
|----|------|
| **职责** | 应用入口、全局主题、路由表、Dio 客户端、环境变量（dev/staging/prod API 地址） |
| **后端依赖** | 无业务 API，仅配置 `BASE_URL` |
| **关键产出** | `lib/app/app.dart`、`lib/app/router/app_router.dart`、`lib/core/network/api_client.dart`、`lib/app/theme/app_theme.dart`、`lib/core/di/providers.dart` |

---

#### Home（首页 / 发现）

| 项 | 说明 |
|----|------|
| **职责** | 每日推荐 Banner、三类分类快捷入口、推荐内容流 |
| **后端 API** | `GET /api/v1/home` 或拆分为 `GET /api/v1/contents/recommended`、`GET /api/v1/daily-tip` |
| **数据字段** | 推荐列表、每日一知（标题、摘要、关联 content_id） |
| **前端状态** | 下拉刷新；首屏骨架屏；失败可重试 |

---

#### Category（分类浏览）

按 **作息（lifestyle）**、**运动（exercise）**、**饮食（diet）** 三个 Tab 或独立列表页展示内容。

| 子模块 | 说明 | 后端 API |
|--------|------|----------|
| **Lifestyle** | 睡眠、早起、规律作息等益处内容 | `GET /api/v1/contents?category=lifestyle` |
| **Exercise** | 有氧、力量、拉伸等运动科普 | `GET /api/v1/contents?category=exercise` |
| **Diet** | 均衡营养、饮水、膳食建议 | `GET /api/v1/contents?category=diet` |

**列表项展示：** 封面图、标题、摘要、标签（最多 2～3 个）、更新时间。

**分页：** 使用 `page`、`page_size` 查询参数；列表底部加载更多（cursor 或 page 由后端约定）。

---

#### Content（内容消费）

| 项 | 说明 |
|----|------|
| **职责** | 内容详情页：好处要点列表、正文（Markdown/HTML）、相关推荐 |
| **后端 API** | `GET /api/v1/contents/{id}` |
| **数据模型** | `BenefitContent`：id、title、summary、cover_url、category、tags、points[]、body、updated_at |
| **交互** | 收藏按钮、分享（可选）、相关推荐点击跳转 |

**好处要点（points）示例结构：**

```json
{
  "title": "改善睡眠质量",
  "description": "固定入睡时间有助于调节生物钟……",
  "icon": "sleep"
}
```

---

#### Search（搜索）

| 项 | 说明 |
|----|------|
| **职责** | 关键词搜索，按标题、标签、摘要匹配 |
| **后端 API** | `GET /api/v1/contents/search?q={keyword}&page=1` |
| **交互** | 防抖 300ms；无结果空状态；搜索历史（本地 Hive，不上报后端） |

---

#### Favorites（收藏）

| 项 | 说明 |
|----|------|
| **职责** | 展示已收藏内容；支持取消收藏 |
| **后端 API（已登录）** | `GET /api/v1/favorites`、`POST /api/v1/favorites`、`DELETE /api/v1/favorites/{content_id}` |
| **未登录方案** | 仅本地 Hive 存储 content_id 列表；登录后可调用同步接口（后端定义） |
| **乐观更新** | 点击收藏立即更新 UI，失败时回滚并 Toast 提示 |

---

#### User / Profile（用户中心）

| 项 | 说明 |
|----|------|
| **职责** | 设置、关于、意见反馈入口、登录/登出（若 v1 需要账号） |
| **后端 API** | `POST /api/v1/auth/login`、`POST /api/v1/auth/refresh`、反馈接口等 |
| **本地** | Token 安全存储（`flutter_secure_storage`）；主题、语言偏好（`shared_preferences`） |

> **MVP 建议：** 若首期不做账号，收藏仅用本地存储；User 模块仅保留设置与关于页。

## 3. 技术栈

| 类别 | 选型 | 说明 |
|------|------|------|
| 框架 | Flutter 3.x / Dart 3.x | 跨平台移动客户端 |
| 状态管理 | flutter_riverpod | `AsyncNotifier` + `Provider`，统一依赖注入 |
| 路由 | go_router | `ShellRoute` 底部导航 + 全屏搜索/详情 |
| HTTP | dio | 拦截器注入 Token、统一 `{code,message,data}` 解析 |
| 序列化 | 手写 DTO `fromJson` | 与 Go `snake_case` JSON 对齐，无 code generation 依赖 |
| 领域模型 | equatable | 不可变 Entity 值对象 |
| 本地缓存 | hive_flutter | 收藏 ID 列表、搜索历史 |
| 安全存储 | flutter_secure_storage | Access / Refresh Token（Auth 预留） |
| 图片 | cached_network_image | 网络封面；无图时用分类色块 + 图标占位 |
| 正文渲染 | flutter_markdown | 渲染后端返回的 Markdown 正文 |
| 结果类型 | `Result<T>` + `Failure` | Repository 层统一成功/失败，UI 层转 `AsyncValue` |

## 5. 与 Go 后端的协作约定

### 5.1 API 通用规范

- **协议：** HTTPS + REST JSON
- **Base URL：** 由环境配置注入，例如 `https://api.healthlive.example.com`
- **版本前缀：** `/api/v1`
- **时间格式：** ISO 8601（`2026-06-12T08:00:00Z`），前端统一用 `DateTime.parse`
- **命名：** JSON 字段建议 **snake_case**（与 Go 常见 tag 一致），Dart 模型用 `@JsonKey(name: 'cover_url')` 映射

### 5.2 统一响应格式（建议与后端对齐）

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

列表分页 `data` 建议：

```json
{
  "items": [],
  "total": 100,
  "page": 1,
  "page_size": 20
}
```

前端在 `api_interceptor` 或 Repository 层解析 `code != 0` 为业务错误。

### 5.3 鉴权

| 场景 | 行为 |
|------|------|
| 公开接口 | 首页、分类列表、详情、搜索无需 Token |
| 需登录接口 | 收藏同步：Header `Authorization: Bearer {access_token}` |
| Token 过期 | 拦截器 401 → 尝试 refresh → 失败则跳转登录 |

### 5.4 错误处理

| HTTP 状态 | 前端处理 |
|-----------|----------|
| 400 | 展示后端 `message`，表单类错误高亮字段 |
| 401 | 清除 Token，引导登录 |
| 404 | 内容不存在页 |
| 5xx | 通用错误页 + 重试按钮 |

### 5.5 核心 API 清单（前端视角）

| 方法 | 路径 | 模块 |
|------|------|------|
| GET | `/api/v1/home` | Home |
| GET | `/api/v1/daily-tip` | Home |
| GET | `/api/v1/contents?category=&page=&page_size=` | Category |
| GET | `/api/v1/contents/{id}` | Content |
| GET | `/api/v1/contents/search?q=` | Search |
| GET | `/api/v1/favorites` | Favorites |
| POST | `/api/v1/favorites` | Favorites |
| DELETE | `/api/v1/favorites/{content_id}` | Favorites |
| POST | `/api/v1/auth/login` | Auth |
| POST | `/api/v1/auth/refresh` | Auth |

> 具体字段以 Go 后端 OpenAPI / Swagger 文档为准；前端 DTO 应与 swagger 生成类型或手写模型保持一致。

## 6. 数据流与分层

```
Page (Widget)
    ↓ 用户操作
Provider / Notifier
    ↓
UseCase
    ↓
Repository (interface)
    ↓
RepositoryImpl
    ↓
RemoteDataSource (Dio → Go API)
    ↓ 可选
LocalDataSource (Hive 缓存)
```

**原则：**

- Widget 不直接调用 Dio
- Domain 层不依赖 `flutter`、`dio`
- API 响应先在 `data/models` 反序列化，再 Mapper 为 `domain/entities` 供 UI 使用

## 7. 环境配置

使用 `--dart-define` 或 `flutter_dotenv` 区分环境：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `API_BASE_URL` | `http://10.0.2.2:8080` | Go 服务地址；Android 模拟器用 `10.0.2.2` |
| `ENV` | `dev` | `dev` / `staging` / `prod` |
| `USE_MOCK` | `true` | `true` 使用内置 Mock；对接后端时设为 `false` |

**Mock 模式（默认，无需后端）：**

```bash
flutter run --dart-define=USE_MOCK=true --dart-define=ENV=dev
```

**本地联调 Go 后端：**

```bash
flutter run \
  --dart-define=USE_MOCK=false \
  --dart-define=API_BASE_URL=http://10.0.2.2:8080 \
  --dart-define=ENV=dev
```

## 8. 开发流程

### 8.1 环境准备

1. 安装 Flutter SDK（>= 3.16）并执行 `flutter doctor`
2. 克隆本仓库
3. **首次运行前** 若缺少 `android/`、`ios/` 等平台目录，执行：
   ```bash
   flutter create . --org com.healthlive --project-name healthlive_client
   ```
4. 安装依赖：`flutter pub get`
5. 默认 Mock 模式可直接运行；联调时启动 Go 后端并设置 `USE_MOCK=false`

### 8.2 开发阶段与当前进度

| 阶段 | 内容 | 依赖后端 | 状态 |
|------|------|----------|------|
| P0 | App Shell、主题、底部导航、路由 | 否 | ✅ 已完成 |
| P1 | Category 列表 + Content 详情 | Mock 可测 | ✅ 已完成 |
| P2 | Home 推荐与每日一知 | Mock 可测 | ✅ 已完成 |
| P3 | Search + 搜索历史 | Mock 可测 | ✅ 已完成 |
| P4 | Favorites（本地 Hive） | 否 | ✅ 已完成 |
| P5 | Auth + 收藏云端同步 | 是 | ⏳ 接口已预留 |

Mock 数据源：`lib/features/content/data/datasources/content_mock_datasource.dart`  
切换方式：`--dart-define=USE_MOCK=false` 即走 `ContentRemoteDataSource`。

### 8.3 代码规范

- **命名：** 文件 `snake_case`，类 `PascalCase`，Provider 以 `Provider` / `Notifier` 结尾
- **异步：** 列表与详情使用 `AsyncValue`，避免在 `build` 里直接 `Future`
- **模型：** API 字段变更时同步更新 DTO 与 Mapper，并注明后端 PR 链接
- **提交：** 建议 `feat(home): ...` / `fix(content): ...` 格式

### 8.4 新增 API 字段流程

1. 更新 `features/content/data/models/` 下对应 DTO 的 `fromJson`
2. 更新 `domain/entities/` 与 `data/mappers/`
3. 若涉及 UI 展示，修改 `presentation/` 对应页面
4. 补充 `test/` 下 Mapper 或 UseCase 单元测试

## 11. 常见问题

**Q: Android 模拟器访问不到本机 Go 服务？**  
A: 使用 `10.0.2.2` 代替 `localhost`；确认 Go 服务监听 `0.0.0.0:8080`。

**Q: 字段名对不上导致解析失败？**  
A: 核对 Go struct 的 `json` tag，在 Dart 侧用 `@JsonKey(name: '...')` 对齐。

**Q: 图片不显示？**  
A: 检查 `cover_url` 是否为完整 URL；HTTPS 证书问题在 dev 环境可让后端提供 HTTP 或配置网络安全策略。

**Q: 何时做离线缓存？**  
A: P1 可不做；用户反馈弱网需求后，在 Repository 层增加「先读 Hive，后台刷新」策略。
