# 内容数据同步（JSON ↔ PostgreSQL）

> 演示 APK 默认 `DATA_SOURCE=json`，读取 `assets/data/` 下与 **PostgreSQL 表同名** 的 JSON 文件，无需启动服务器。  
> 与数据库保持一致：在 pgAdmin 维护表数据 → 按表导出 JSON → 覆盖对应文件 → 重新打包。

---

## 1. JSON 文件与数据库表对照

| JSON 文件 | PostgreSQL 表 | JSON 模式是否使用 | 说明 |
|-----------|---------------|-------------------|------|
| `categories.json` | `categories` | ✅ 是 | 内容分类主表（作息 / 运动 / 饮食） |
| `contents.json` | `contents` | ✅ 是 | 内容主表，详情/列表/搜索的数据源 |
| `content_benefit_points.json` | `content_benefit_points` | ✅ 是 | 详情页「核心好处」，按 `content_id` 关联 |
| `content_tags.json` | `content_tags` | ✅ 是 | 标签，按 `content_id` 关联 |
| `daily_tips.json` | `daily_tips` | ✅ 是 | 首页「每日一知」，取 `tip_date` 最新一条 |
| `home_recommendations.json` | `home_recommendations` | ✅ 是 | 首页推荐，按 `sort_order` 排序 |
| `users.json` | `users` | ⏳ 预留 | 登录（P5）未接入，当前可空数组 |
| `user_favorites.json` | `user_favorites` | ⏳ 预留 | 云端收藏未接入；收藏现走 Hive 本地 |

**种子数据 SQL：** 见 [数据库种子SQL.md](数据库种子SQL.md)（与 JSON 一一对应，可复制到 pgAdmin 执行）。

**重新生成 JSON + SQL：** `python tool/generate_seed_data.py`

客户端在 JSON 模式下会 **模拟 SQL JOIN**：以 `contents` 为主表，通过 `category_id` / `category` 关联 `categories`，并关联 points、tags；首页再读 `daily_tips` + `home_recommendations`。

代码入口：`lib/features/content/data/datasources/content_json_datasource.dart`

## 2. 各文件字段说明

### `categories.json`

```json
{
  "categories": [
    {
      "id": 1,
      "code": "lifestyle",
      "name": "作息",
      "description": "睡眠、早起、规律作息等生活方式科普",
      "icon": "bedtime_outlined",
      "color": "#5B8DEF",
      "sort_order": 1,
      "published": true,
      "created_at": "2026-06-22T02:42:11.169Z",
      "updated_at": "2026-06-22T02:42:11.169Z"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 分类 ID |
| `code` | 是 | API 枚举值：`lifestyle` / `exercise` / `diet` |
| `name` | 是 | 显示名：作息 / 运动 / 饮食 |
| `description` | 否 | 分类简介 |
| `icon` | 否 | Material Icons 名称，如 `bedtime_outlined` |
| `color` | 否 | 主题色 HEX，如 `#3D8B7A` |
| `sort_order` | 建议 | Tab 与列表排序，升序 |
| `published` | 建议 | `true` 才在 App 中展示 |

### `contents.json`

```json
{
  "contents": [
    {
      "id": 1001,
      "category_id": 1,
      "title": "…",
      "summary": "…",
      "cover_url": "",
      "body": "## Markdown 正文",
      "published": true,
      "sort_order": 0,
      "created_at": "2026-06-22T02:42:11.169Z",
      "updated_at": "2026-06-10T08:00:00.000Z"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 内容 ID，规则：`category_id * 1000 + 序号`（如 `1011`） |
| `category_id` | 是 | 关联 `categories.id` |
| `title`, `summary`, `body` | 是 | 标题、摘要、Markdown 正文 |
| `cover_url` | 否 | 封面 URL；当前使用 [Unsplash](https://unsplash.com) 免费图（见 `tool/generate_seed_data.py` 中 `COVER_URLS`） |
| `published` | 建议 | `true` 才在 App 中展示；也可用 `status: "published"` |
| `updated_at` | 是 | ISO 8601，列表排序用 |

### `content_benefit_points.json`

| 字段 | 必填 | 说明 |
|------|------|------|
| `content_id` | 是 | 关联 `contents.id` |
| `title`, `description` | 是 | 好处标题与说明 |
| `icon` | 否 | 如 `sleep`、`walk` |
| `sort_order` | 建议 | 展示顺序，升序 |

### `content_tags.json`

| 字段 | 必填 | 说明 |
|------|------|------|
| `content_id` | 是 | 关联 `contents.id` |
| `tag` | 是 | 标签文案，搜索会匹配 |

### `daily_tips.json`

| 字段 | 必填 | 说明 |
|------|------|------|
| `content_id` | 是 | 关联内容，点击跳转详情 |
| `title`, `summary` | 是 | 首页卡片展示 |
| `tip_date` | 建议 | 日期 `YYYY-MM-DD`，取最新一条 |

### `home_recommendations.json`

| 字段 | 必填 | 说明 |
|------|------|------|
| `content_id` | 是 | 推荐的内容 ID |
| `sort_order` | 是 | 越小越靠前 |
| `published` | 建议 | `true` 才展示；或 `is_active: true` |

### `users.json` / `user_favorites.json`

登录与云端收藏尚未接入，**演示包可保持空数组 `[]`**。接入 Auth 后需补充：

**users：**

| 字段 | 说明 |
|------|------|
| `id` | UUID |
| `email` | 登录邮箱 |
| `password_hash` | bcrypt 哈希（勿放明文密码） |
| `nickname` | 显示名 |

**user_favorites：**

| 字段 | 说明 |
|------|------|
| `user_id` | 关联 `users.id` |
| `content_id` | 关联 `contents.id` |

## 4. 数据来源切换

```bash
# 演示包（默认 json）
flutter build apk --dart-define=DATA_SOURCE=json

# 对接服务器
flutter build apk --dart-define=DATA_SOURCE=server --dart-define=API_BASE_URL=https://api.example.com
```

## 5. pgAdmin 按表导出 JSON

pgAdmin **没有**「整表一键导出 JSON」菜单。推荐：

1. 在 Query Tool 对**每张表**执行，例如：
   ```sql
   SELECT json_agg(t) FROM contents t;
   ```
2. 包装为 `{ "contents": [ ... ] }` 格式（键名与表名一致）
3. 覆盖 `assets/data/<表名>.json`

或用 DBeaver 等工具导出 JSON 后改外层键名。

## 6. 工作流

```
pgAdmin 编辑 PostgreSQL 表
    ↓ 按表导出 JSON
assets/data/*.json（8 个文件）
    ↓ flutter build apk（DATA_SOURCE=json）
演示 APK（与库数据一致，无需服务器）
```
